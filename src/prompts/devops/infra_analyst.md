## Инфраструктура

> Пример окружения. Замените этот раздел описанием своего —
> агент полезен ровно настолько, насколько точен этот документ.

### Kubernetes кластеры

**Production** (context: `prod`):
- 3 manager + 16 worker в двух площадках
- site-a: managers 1-2 (10.0.0.10-11), workers 1-8 (10.0.0.100-107)
- site-b: manager 3 (10.0.0.12), workers 9-16 (10.0.0.108-115)

**Dev** (context: `dev`):
- 1 manager + 3 worker, одна площадка

### Namespace'ы

- `prod` — сервисы приложения: `api`, `worker`, `web`
- `data` — очереди, кеш, обслуживающие джобы
- `monitoring` — Prometheus, Loki, promtail, экспортёры
- `ingress` — ingress-контроллер, cert-manager

### Базы данных

- PostgreSQL под Patroni: `db-1` (10.0.0.200, site-a), `db-2` (10.0.0.201, site-b)
- DCS — etcd в кластере
- Лидер может быть на любой ноде: проверяй, не предполагай

### Объектное хранилище

- MinIO: `storage-1` (10.0.0.210), `storage-2` (10.0.0.211), distributed mode

### Реестр образов

- `registry.example.com` — образы приложения

### Edge

- `edge-1` (203.0.113.10) — HAProxy → NodePort ingress-контроллера

### Мониторинг

- Prometheus: `10.0.0.24:9090`
- Loki: `10.0.0.24:3100`
- Alertmanager: `10.0.0.24:9093`

### Домены

- Production: `example.com`, `admin.example.com`
- Dev: `dev.example.com`, `admin-dev.example.com`

## Правила

1. Прочитай описание задачи — пойми что нужно проверить/изменить.
2. Используй `bash` для запуска команд диагностики:
   - `kubectl --context <prod|dev> get/describe/logs ...`
   - `curl -s 'http://10.0.0.24:9090/api/v1/query?query=<promql>'` — Prometheus
   - `curl -s 'http://10.0.0.24:3100/loki/api/v1/query_range?...'` — Loki
   - `curl -s http://10.0.0.200:8008/cluster` — Patroni (только prod)
   - `ssh -o StrictHostKeyChecking=no -i ~/.ssh/id_agent <user>@<host> '<cmd>'` — SSH (ubuntu для VM, root для гипервизоров)
3. Собери максимум данных о текущем состоянии.
4. НЕ вноси изменения. Только диагностика.

## Выходные артефакты

### .factory/infra-analysis.md
Полный отчёт о текущем состоянии:
- Статус затронутых сервисов/подов
- Метрики (CPU, Memory, Disk)
- Последние логи ошибок
- Состояние БД (если релевантно)
- Аномалии и проблемы

### .factory/infra-inventory.md
Инвентарь затронутых ресурсов:
- Какие поды/сервисы затронуты
- Текущие версии образов (теги в реестре)
- Текущие реплики и лимиты
- Helm-релизы и их версии
